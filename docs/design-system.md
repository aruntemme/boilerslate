# Design system

Built on [shadcn/ui](https://ui.shadcn.com) in the **`base-nova`** style, over
[Base UI](https://base-ui.com) primitives and Tailwind v4.

`/playground` renders every component live. Change a token and check it there.

## Base UI, not Radix

The primitives are `@base-ui/react`. Most shadcn examples online are from the
Radix era and will not transfer directly:

- there is no `asChild`; composition uses a `render` prop
- `DropdownMenuLabel` is a `GroupLabel` and **throws at runtime** unless it sits
  inside a `DropdownMenuGroup` or `DropdownMenuRadioGroup`

That second one typechecks and builds fine. It only fails in a browser, so open
the page after touching a menu.

## Themes

Two independent axes, both on `<html>`:

| Axis | Set by | Values |
| --- | --- | --- |
| Theme | `data-theme="<id>"` | emerald, violet, blue, cyan, rose, orange, amber, neutral |
| Mode | `.dark` class | light / dark |

So `<html class="dark" data-theme="violet">` is violet-dark — 8 themes × 2
modes.

- Token sets — `packages/ui/src/styles/themes.css`
- Registry (ids, labels, preview swatches) — `packages/ui/src/lib/themes.ts`

Adding a theme means editing **both** files and nothing else; the switcher and
the settings page read the registry.

### Why the selectors look odd

Theme blocks are written `:root[data-theme="x"]`, not `[data-theme="x"]`.
Specificity 0,2,0 beats the `:root` defaults in `globals.css` (0,1,0)
regardless of import order. Shortening them makes the defaults win and every
theme silently stops applying.

### No flash on load

`THEME_INIT_SCRIPT` (in `lib/themes.ts`) is inlined into `<head>` and applies
the stored theme before first paint. `ThemeProvider` takes over after
hydration. Preferences persist to `localStorage`.

## Tokens

Use them; never hard-code a colour.

```
bg-background  bg-card  bg-muted  bg-primary  bg-destructive
text-foreground  text-muted-foreground  text-primary-foreground
border-border  ring-ring
--chart-1 … --chart-5
```

A hard-coded hex will not follow the theme, and will look wrong in one mode or
the other.

## Radius

`--radius` is editable at runtime from Settings. The steps are
**multiplicative**:

```css
--radius-sm: calc(var(--radius) * 0.6);
--radius-lg: var(--radius);
--radius-xl: calc(var(--radius) * 1.4);
```

Additive offsets cannot reach zero — `calc(0rem + 4px)` is still 4px — so
"Square" would not be square. Keep them multiplicative.

## Density

`--card-spacing` is overridden to `1.25rem` in `globals.css`. The generated
default of `1rem` reads cramped once cards carry charts and stat rows.

For the uppercase-label-over-large-number pattern, use the stat primitives in
`components/stat.tsx` — `StatLabel`, `StatValue`, `StatDelta`, `StatGroup` —
rather than re-inventing it per page.

## Cursors

Tailwind v4's Preflight sets `cursor: default` on buttons, so pointers are
restored explicitly in `globals.css` for buttons, links, labels and the
interactive ARIA roles.

The menu and select overrides there are **unlayered on purpose**: those items
ship a `cursor-default` utility class, and utilities always beat `@layer base`.
Moving them into a layer breaks them silently.

## Charts

[Recharts](https://recharts.org) through the shadcn `ChartContainer`. Colours
come from the theme's `--chart-1..5` ramp, so charts re-skin with the theme.

> **Any chart inside a grid or flex parent needs `min-w-0` on that parent.**
> Grid and flex items default to `min-width: auto`, so the chart's measured
> width widens its own track, which widens the chart again. The loop blows the
> layout out and squashes the plot. It still builds and still renders — only a
> browser catches it.

## Vendored vs ours

| Path | Treat as |
| --- | --- |
| `packages/ui/src/components/*.tsx` | **Vendored.** Generated by the shadcn CLI and regenerated on upgrade. Do not hand-edit; wrap instead. This is why a11y and a few other rules are relaxed there in `biome.json`, and nowhere else. |
| `packages/ui/src/components/ai/*` | **Ours.** Written against these tokens. Edit freely. |
| `packages/ui/src/components/stat.tsx` | **Ours.** |

Add a component with `bunx --bun shadcn@latest add <name>` from `packages/ui`,
then render it on `/playground`.
